# 退職願・退職届 自動作成ツール MVP

氏名・会社名・退職希望日などを入力するだけで、正しい形式の退職願・退職届の文面を自動生成し、コピーできるWebアプリ。HAKONIWA LABの9本目のツールで、初の**ジェネレーター型**(クイズ診断型・計算機型に続く3つ目のパターン)。[[career-checker]]の「退職を切り出しにくい」という悩みと[[retirement-simulator]]の「退職金」というテーマの両方から自然につながる企画。

## ローカルでの動作確認

```
cd resignation-letter-generator
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開く。`index.html` を直接ダブルクリックしても動作する(外部通信は一切行わない)。


## 文面生成ロジックについて

`js/generate.js`の`buildLetterText`が、日本の一般的なビジネス慣習に沿った書式で文面を組み立てる。

- **退職願 vs 退職届**: 「退職願」は会社にお願いする形で受理前なら撤回できる余地がある一方、「退職届」は退職の意思を通知する形で原則撤回できない。それぞれ結びの文言を変えている(「〜お願い申し上げます」/「〜退職いたします」)。
- **和暦変換**: 日付は西暦入力から令和表記に変換して出力(`toEraDate`)。令和1年(2019年)以降のみ対応、それ以前は西暦のままフォールバック。
- **退職理由**: プリセット(一身上の都合により/契約期間満了に伴い/転居に伴い/家庭の事情により)は接続助詞まで含めた一続きの句として保持し、本文の結び(「〜、令和◯年◯月◯日をもって退職いたします」)にそのままつなげる設計。自由入力欄も同様に助詞まで含めて入力してもらう(「一身上の都合により」+「により」のような二重助詞バグを防ぐため)。

### 発見した不具合と修正(2026-08-02)

初期実装で2件のバグを開発中に発見・修正:

1. **日付のタイムゾーンバグ**: 「本日の日付」を`new Date().toISOString().slice(0, 10)`で取得していたところ、`toISOString()`はUTCに変換するため、日本時間(UTC+9)の深夜〜早朝(0:00〜8:59JST)に実行すると前日の日付になってしまう不具合があった。ローカルの年月日をそのまま組み立てる`todayLocalDateString()`に置き換えて修正。
2. **理由欄の二重助詞バグ**: 当初「理由の名詞句」+固定の「により」を機械的に結合する設計だったため、ユーザーが既に助詞を含む理由(例:「転居のため」)を入力すると「転居のためにより」という不自然な文になっていた。理由を「接続助詞まで含めた一続きの句」として扱う設計に変更して解消。
